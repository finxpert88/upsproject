# UPS Fleet Monitor — 修订3 Dashboard DEMO

打开 **UPS-Fleet-DEMO.html**，无需安装、联网或启动服务器。CSS和JavaScript全部内嵌。

依据：当前 `doc/planning/UPS-Fleet-FIN-POD-FSD-v0.1.md` **v0.1 修订3**（Dashboard与KPI保真修订，待评审），重点为§5.2/5.3/5.8/5.9及§17。基线SHA-256见baseline.json。修订2原型未覆盖，保留供比较。

## 本轮页面

- 默认仪表盘：横向UPS tabs、三分区Hero、110px健康环、三列两行六卡、全宽本机告警与事件。
- 三类固定样例：UPS-01完整能力、UPS-02风险、UPS-03缺失。每台、每串、每模块拥有自己的值与额定容量，禁止按站点猜额定值。
- 恢复电池SOH/SOC趋势、负载条与刻度/趋势、电容mini-gauge、空气质量、干燥/有水/未知、切换时长和完整日期、三行维护/预测展望。
- 正常主导航：仪表盘、设备清单、告警事件、工程。工程下保留配置/验收/诊断/审计。
- 右上角“•••”打开演示工具：三类夹具、历史加载/缺失/失败/缺口、评分缺失、角色范围、既有异常场景、32项KPI对照。
- 默认选择最后查看且仍授权的设备，否则名称排序首台accepted设备。详情深链使用同一Dashboard。

## 建议评审

1. 首次打开：UPS-01健康92/100、SOH94%、负载58%、电容88%、切换4ms、带时区的事件日期、三行展望全部可见。
2. 切换电池串A/B，观察电压/阻抗/温度/SOH/趋势变化；切换SOC/SOH；切换°C/°F。
3. UPS-02：负载110%完整显示，环91分不掩盖严重风险；已确认严重告警仍活动。
4. UPS-03：过期评分中性环、电容空轨、缺历史框、漏水未知、无切换事件、三个待评估展望行均保留位置。
5. 右上角工具：历史失败不遮盖主值；缺口断线；评分缺失不会拿SOH替代；查看者仅B站点。
6. 设备清单/告警/工程延续修订2交互：过滤、单条确认、未知结果核对、草稿、校验、发布/冲突/失败、验收和审计。

## 验证

运行 `node verify.cjs`：30项Node VM逻辑及生成标记检查，结果见verification.json。覆盖默认路由、导航、32个KPI标记及关键数值图形、夹具隔离、状态切换、授权范围、源评分配置约束、确认/发布。

这些检查不等于视觉验收。由于此前浏览器URL安全策略拒绝本地文件，本轮没有绕过限制，未取得真实页面截图。FSD UI-01～12（含1366×900、1440×1000、390宽、200%缩放和与原DEMO实屏对照）全部保留“待人工视觉验收”。CSS按FSD配置1240px内容壳、48px背景网格、3px面板角、18px间距、3/2/1列断点；不声称这些源码检查等于实屏通过。

本DEMO无FIN连接，不涉及设备控制。健康分与预测窗口是明确标识的固定示例，未实现现场评分/预测接口；正式Ractive模块化、FIN权限、事务、幂等、采集/历史、性能与版本兼容仍是后续生产实现。

## 文件

- UPS-Fleet-DEMO.html：单文件交付入口。
- index.html + app.js + dashboard.js + styles.css + dashboard.css：便于继续编辑的拆分源码。
- build.cjs：重新打包单文件并更新基线记录。
- verify.cjs / verification.json：代码级检查与结果。
- baseline.json：FSD版本、哈希、夹具与验收边界。

修改后运行 `node build.cjs` 更新单文件。
